# Working agreements

- Keep implementations simple and easy to explain.
- I lead the TDD process.
- Modify code only when explicitly requested.
- Use braces and blank lines between logical steps.
- Avoid unnecessary interfaces and helper classes.
- Test one behavior at a time.
- Use clean sample data; test normalization separately.
- Prefer record comparisons over property-by-property assertions.
- Keep methods compact and short, prefer use of helper functions
